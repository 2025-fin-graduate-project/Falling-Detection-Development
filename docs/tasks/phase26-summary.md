## 결론

- **patience 증가가 역효과**: val_event_min_pr은 에포크마다 노이즈가 크기 때문에 patience=15는 spurious peak를 과도하게 추적하다 좋은 weight를 지나침.
- **GRU(256,128)은 patience=15로도 오히려 악화**: 더 많은 파라미터 + 노이즈 메트릭 조합이 과적합 유발.
- **P21-v01 (GRU(128,64), patience=5)이 최적 구성 확정**: 우연이 아닌 실제 최적이었음.
- **0.93 도달 전략 전환**: 모델 크기/훈련 시간 축은 소진됨 → seed 다양성 + checkpoint monitor 안정화(Phase 27)로 전환.
