## 1.4 전처리 변인: 윈도우 크기 (Window Size)

**윈도우 크기 = 한 번에 모델에 입력하는 연속 프레임 수**

| 크기 | 시간 (15fps) | 설명 |
|------|------------|------|
| 60f | 4.0초 | Phase 1~2 기본값 (미명시 실험) |
| 40f | 2.7초 | Phase 3~5, 36~40 표준 |
| 35f | 2.3초 | Phase 38 탐색 |
| 30f | 2.0초 | Phase 3, Phase 36~39 비교 |

### 비교 결과

**구 프레임워크 (video MinP, GRU(256,128), filtered, kp12):**

| 윈도우 | test video MinP | 실험 |
|--------|----------------|------|
| 60f | 0.9556 | P1-v16 (Phase 1 기본값) |
| **40f** | **0.9556** | P3-v02 (Phase 3) |
| 30f | 0.9404 | P3-v07 (Phase 3) |

→ 60f ≈ 40f > 30f: 40f가 60f와 동등하면서 컨텍스트 25% 절감

**신 프레임워크 (window MinP, GRU(128,64), kp13, pure-window):**

| 윈도우 | test window MinP | event_vote MinP | FN | FP | 실험 |
|--------|-----------------|----------------|----|----|------|
| **40f** | **0.9404** | 0.8816 | 1,066 | 1,040 | P37-pure-kp13-w40-gru |
| 35f | 0.9348 | 0.8947 | 818 | 781 | P38-vel-w35-gru |
| 30f | 0.9255 | 0.9035 | 702 | 596 | P37-pure-kp13-w30-gru |

> event_vote에서는 30f가 약간 유리(FP↓)하나, window MinP 기준 40f가 일관되게 최고

**결론**:
- **최적 윈도우: 40f (2.7초)**
- 60f는 낙상 전 정상 구간이 과도하게 포함되어 불필요한 컨텍스트 → 40f와 동등하나 비효율
- 30f는 post-fall 자세(쓰러진 상태 유지) 포착 불완전 → window MinP 하락
- 35f는 중간점이나 명확한 이점 없음

## 1.5 전처리 변인: 윈도우 레이블링 방식

낙상 영상의 한 윈도우는 낙상 전·중·후 구간이 혼재할 수 있음.

| 방식 | 설명 | 레이블 판단 |
|------|------|-----------|
| **Mixed label** | 윈도우 내 마지막 프레임 기준 | 경계 윈도우에 노이즈 레이블 |
| **Pure-window** (margin=5) | 낙상 이벤트 끝에서 margin 이내 윈도우만 fall로 레이블 | 경계 윈도우 배제 |

### 비교 결과 (Phase 36 vs Phase 37)

| 레이블링 방식 | test window MinP | 실험 |
|-------------|----------------|------|
| Mixed (경계 포함) | 0.7843 | P36-kp13-w40-gru |
| **Pure (margin=5)** | **0.9404** | P37-pure-kp13-w40-gru |
| **차이** | **+0.1561** | |

> margin 효과 추가 검증 (Phase 37):
> - margin=0: 0.9350 (P37-pure-m0-kp13-w40-gru)
> - margin=5: **0.9404** ← 최적
> - margin=10: 0.9341 (P37-pure-m10-kp13-w40-gru) — fall 학습 데이터 과도 제거

**결론**: Pure-window 레이블링(margin=5)이 가장 결정적인 성능 도약 요인 (+0.156).
경계 윈도우의 노이즈 레이블이 모델 학습을 심각하게 방해했음.

## 1.6 라벨 정의 변인: 이진 vs 3-class

| 라벨 방식 | 정의 | 사용 Phase |
|----------|------|-----------|
| LB-2 (binary) | 0=비낙상, 1=낙상(falling+fallen) | 전 Phase |
| LB-3 (3-class) | 0=정상, 1=falling(낙상중), 2=fallen(쓰러짐) | Phase 12 탐색 |

### LB-3 결과 (Phase 12)

| 실험 | 변경점 | test event MinP | FP | FN |
|------|--------|----------------|----|----|
| P12-v01 (기준) | LB-2 alpha=0.10 | 0.9061 | 23 | 20 |
| P12-v02 | LB-3 only | 0.8821 | 20 | 29 |
| P12-v03 | LB-3 + hard-neg | 0.8866 | 18 | 28 |
| P12-v04 | LB-3 + hard-neg + kp12 | 0.8911 | 16 | 27 |

**결론**: LB-3는 FP를 줄이지만 FN이 크게 증가 → MinP 하락. **LB-2가 최적.**
falling과 fallen을 분리해 학습해도 decision boundary 개선 효과 없음.

## 1.8 Keypoint 신뢰도 분위별 성능 (추가 실험 6)

**배경**: MoveNet은 각 keypoint에 신뢰도 점수(0~1)를 출력한다. 신뢰도가 낮을수록 keypoint 위치가 불확실하고 낙상 검출 성능이 저하될 수 있다.

**방법**: 테스트 영상별 평균 keypoint 신뢰도를 계산(17 kp × 모든 프레임), Q1~Q4 분위로 나눠 event MinP 측정.

### 신뢰도 분위별 MinP (P42-kp17-w60 기준)

| 분위 | 신뢰도 범위 | 비디오 | MinP | NFallPrecision | 비고 |
|---|---|---|---|---|---|
| Q1 (최저) | ≤ 0.371 | 214 | **0.450** | 0.450 | FP 급증 |
| Q2 | 0.371–0.425 | 213 | 0.860 | 0.878 | |
| Q3 | 0.425–0.504 | 213 | 0.941 | 0.941 | |
| Q4 (최고) | > 0.504 | 213 | **0.980** | 0.980 | FP=0 |

**발견**:
- Q4 (고신뢰도): FP=0, MinP=0.980 — 신뢰도가 높으면 오검출 없음
- Q1 (저신뢰도): NFallPrecision 0.29~0.45로 급락 — 비낙상 오검출이 주요 실패 원인
- raw 모델(P41-raw-kp7-w40)은 Q1에서 FN도 급증 (필터 없이 노이즈 그대로 학습)
- filtered 모델(kp13, kp17)은 Q1에서도 fall recall ≥ 0.94 유지 (낙상 감지 안정적)

**결론**: 저신뢰도 keypoint는 비낙상 구간에서 낙상처럼 보이는 패턴을 만들어 FP를 유발한다. 실배포 시 신뢰도 임계값 필터링(예: 신뢰도 < 0.3인 프레임은 이전 keypoint로 대체)이 Q1 성능 저하를 완화할 수 있다.
